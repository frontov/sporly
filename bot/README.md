# Sporly Telegram bot

Бот ищет спортивные старты в каталоге Sporly, присылает новые события по
подписке, напоминает об избранных стартах и монетизируется партнёрскими
размещениями.

## Интерфейс

- При первом `/start` — короткий опрос: виды спорта и регионы.
- «Ближайшие» показывает только старты из сохранённых интересов.
- «✨ Рекомендуемые» — подборка стартов, которую админ ведёт на сервере.
- «Мои интересы» — отдельный экран, где можно изменить подборку и
  уведомления.
- «🔔 Уведомления» — три независимые настройки: новые старты по
  сохранённым фильтрам, ежедневный дайджест и напоминания об избранном.
- В одном сообщении — несколько стартов (4 на страницу), без бесконечных
  карточек по одному.
- Цветной маркер `🔴 →` под списком открывает подробную карточку старта.
- В подробной карточке — избранное, «Поделиться» и переход на сайт.
- Только inline-кнопки, без постоянной нижней клавиатуры.
- На каждом экране есть подсказка, что нажать дальше: на главной, в
  поиске, в мастере интересов, в карточке старта, в избранном и в
  уведомлениях. Полная инструкция — кнопка «❓ Как пользоваться» или `/help`.
- Старые reply-кнопки автоматически убираются при `/start`.

## Что умеет

- **Опрос при старте**: какие виды спорта и регионы интересны.
- **Поиск** по названию, городу, виду спорта и региону.
- **Фильтры-чипы**: вид спорта и регион, несколько вариантов одновременно.
- **Избранное** с напоминаниями за 7, 3 и 1 день и в день старта, списком
  по 5 событий на страницу.
- **Рекомендуемые** — общая подборка стартов от Sporly. Админ добавляет
  события из карточки кнопкой «⭐ В рекомендуемые», список хранится в
  backend и доступен всем пользователям.
- **Мои интересы** — сохранённые виды спорта и регионы для «Ближайших»
  и уведомлений.
- **Уведомления** — отдельные переключатели: новые события по фильтрам,
  дайджест и напоминания об избранном. Можно включить любую комбинацию.
- **Ежедневный дайджест** ближайших стартов.
- **Поделиться стартом** — deep link на бота с карточкой события.
- **Приглашения** — ссылка `ref_<id>`, учёт приглашённых.
- **Атрибуция рекламы** — ссылка `src_<campaign>` для запусков в Telegram Ads
  и у других каналов.
- **Партнёрские слоты** в поиске и дайджесте со статистикой показов,
  переходов и CTR.
- **Админка**: состояние каталога, воронка, источники трафика, партнёры,
  рассылка.

Бот не берёт денег с пользователей. Монетизация — продажа партнёрских
размещений организаторам стартов и рекламодателям.

## Уведомления

- **Новые старты по фильтрам** — одно сообщение в день. Бот проверяет
  каталог каждые 15 минут, но отправляет подборку не чаще раза в сутки.
- **Дайджест** — раз в день утром, по умолчанию в 09:00 МСК. Для новых
  пользователей выключен — включается отдельно на экране «🔔 Уведомления».
- **Напоминания об избранном** — за 7, 3 и 1 день и в день старта.
- **Регистрация в избранном** — отдельное сообщение, когда у избранного
  старта открывается регистрация, а также за день и в день её закрытия.
  Состояние перепроверяется по каталогу, поэтому уведомление придёт, даже
  если источник не публиковал дату открытия заранее.
- Ночью бот не отправляет проактивные сообщения. Тихие часы по умолчанию
  с 22:00 до 09:00 МСК (`QUIET_HOURS_START`, `QUIET_HOURS_END`).

Все три настройки независимы: их можно включать и выключать на экране
«🔔 Уведомления» или командой `/notifications`.

## Локальный запуск

Нужен запущенный backend Sporly на `http://localhost:8000`.

```bash
cd bot
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# вставьте BOT_TOKEN от @BotFather
python -m app.main
```

Проверка:

```bash
python -m compileall app
python -m unittest discover -s tests -v
```

## Переменные окружения

Основные:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | токен от @BotFather |
| `API_BASE_URL` | адрес backend, локально `http://localhost:8000`, в Docker `http://backend:8000` |
| `ADMIN_TELEGRAM_IDS` | ID админов через запятую |
| `PUBLIC_BASE_URL` | публичный HTTPS-адрес для трекинга партнёрских ссылок, например `https://sporly.ru` |
| `PARTNER_CONTACT` | контакт для раздела «Реклама» |
| `PARTNER_IMPRESSION_PER_USER_DAY` | сколько раз одному пользователю показывать партнёрский слот в день |
| `POLL_INTERVAL_SECONDS` | как часто проверять новые события (по умолчанию 900) |
| `DIGEST_HOUR_UTC` | час отправки дайджеста в UTC (по умолчанию 6 = 9:00 МСК) |
| `REMINDER_CHECK_INTERVAL_SECONDS` | частота проверки напоминаний |
| `MAX_NOTIFICATIONS_PER_TICK` | максимум событий в одном ежедневном сообщении о новых стартах (в списке по 4 на страницу) |
| `QUIET_HOURS_START` | начало тихих часов по Москве (по умолчанию 22) |
| `QUIET_HOURS_END` | конец тихих часов по Москве (по умолчанию 9) |
| `DATABASE_FILE` | путь к SQLite, по умолчанию `app/data/sporly.db` |

Полный список — в `.env.example`.

## Партнёрские размещения

Конфиг: `app/config/partners.json`. Пример — `app/config/partners.example.json`.

```json
{
  "partners": [
    {
      "id": "moscow-marathon",
      "enabled": true,
      "label": "Партнёр",
      "title": "Московский марафон",
      "text": "Регистрация на дистанции 5, 10 и 42 км открыта.",
      "button_text": "Регистрация",
      "url": "https://example.com/marathon?sub={uid}",
      "placements": ["search", "digest"],
      "cities": ["Москва"],
      "categories": ["Бег"],
      "keywords": [],
      "weight": 1,
      "starts_at": "2026-01-01",
      "ends_at": "2026-12-31"
    }
  ]
}
```

Правила:

- `placements` — `search` и/или `digest`.
- `cities` и `categories` сужают показы. Если список задан, слот показывается
  только когда у пользователя выбран подходящий фильтр.
- `keywords` — показывать только при совпадении с поисковым запросом.
- `url` может содержать `{uid}` — туда подставится Telegram ID пользователя.
- Если задан `PUBLIC_BASE_URL`, ссылка идёт через `/go/<partner_id>?uid=<id>`,
  и бот считает переходы. Иначе используется прямой URL.
- Пустые `cities`, `categories`, `keywords` = без ограничений.
- Не ставьте `enabled: true` на демо-слот.

Конфиг перечитывается автоматически при изменении файла (раз в 30 секунд).

### Как продавать размещения

1. Соберите аудиторию бота рекламой в Telegram и пабликах.
2. Покажите организатору статистику: `/stats` и `/partners` в админке.
3. Настройте слот с таргетингом на его вид спорта и регион.
4. Считайте показы, переходы и CTR. Оплата — фиксированная или за переходы.

В карточках партнёров всегда отображается метка «Партнёр»/«Реклама». Это
требование прозрачности и заодно повышает доверие к подборке.

## Атрибуция трафика

Ссылки для запусков:

```text
https://t.me/sporly_bot?start=src_<campaign>
```

Например: `src_habr`, `src_vk_runners`, `src_tg_ads_october`.

Статистика по кампаниям — `/stats` → «Источники трафика».

Приглашения:

```text
https://t.me/sporly_bot?start=ref_<telegram_id>
```

## Статистика

Кнопка «📊 Статистика» показывается только администраторам из
`ADMIN_TELEGRAM_IDS`. Внутри:

- сводка за 7 или 30 дней;
- что ищут пользователи: запросы, виды спорта, регионы;
- куда переходят: старты и партнёрские ссылки;
- список пользователей с количеством поисков, переходов и избранного;
- карточка пользователя: последние поиски и переходы.

Чтобы считались переходы на сайты стартов, задайте `PUBLIC_BASE_URL`
(в production это `https://sporly.ru`). Ссылки пойдут через
`/go/event/<token>` и будут логироваться.

## Админка

Команды доступны только ID из `ADMIN_TELEGRAM_IDS`:

- `/admin` — список команд
- `/status` — backend и каталог
- `/stats` — пользователи, подписки, поиски, уведомления, источники
- `/featured` — список рекомендуемых, удаление и добавление по ID/ссылке
- `/partners` — показы, переходы, CTR по слотам
- `/reload` — сбросить кэш API и перечитать партнёров
- `/broadcast <текст>` — рассылка всем пользователям

Рекомендуемые:

- Откройте карточку старта и нажмите «⭐ В рекомендуемые».
- Или выполните `/featured <event_id>` / `/featured <ссылка на событие>`.
- `/featured` без аргумента показывает список с кнопками удаления.

Список хранится на backend в `backend/app/data/featured_events.json`
(каталог смонтирован в volume) и отдаётся публично через
`/api/events/featured`. Боту нужен тот же `ADMIN_TOKEN`, что и backend.

## HTML-виджеты (dev)

Bot API 10.4 добавил HTML-виджеты: небольшой HTML-документ живёт прямо в
сообщении, а бот меняет его состояние через `chat_data`. Виджет может
отправить боту запрос кнопкой, бот получает `widget_query` и отвечает.

В боте есть экспериментальная команда для администраторов:

```text
/widget                 — ближайшие старты виджетом (нужен backend)
/widget карточка        — один ближайший старт карточкой
/widget <запрос>        — поиск и выдача виджетом
/widget демо            — демо-карточка без backend
/widget демо список     — демо-список без backend
/widget панель          — кнопки для демо
```

Что важно:

- В production Bot API 10.4 разрешает виджеты только в личном чате с ботом;
  группы, inline-режим и пересылка пока работают на test server.
- HTML-код виджета неизменяем после отправки. Меняется только состояние:
  `chat_data` для конкретного сообщения и `public_data` для shared-виджета.
- Внутри виджета нет сети: ни `fetch`, ни внешних картинок и скриптов.
  Единственный канал наружу — `TelegramWidget.request()`.
- Лимиты: 32 КБ HTML, 4 КБ после сжатия, состояние — 1 КБ, высота 50–600 px.
- Кнопки `☆`, «Показать ещё» и «Обновить» обрабатываются в `app/widgets.py`.
  Сессии виджетов сейчас хранятся в памяти процесса: после рестарта старые
  виджеты ответят «Виджет устарел». Для production нужен SQLite/Redis.
- aiogram 3.13 ещё не знает методы и типы виджетов, поэтому в
  `app/widgets.py` используются собственные `TelegramMethod`, а обновления
  `widget_query` / `shared_widget_query` обрабатываются вручную на
  `Dispatcher.update`. Предупреждение aiogram о неизвестном типе обновления
  подавлено в `app/main.py`.

### `/app` — весь интерфейс в одном виджете

`/app` (или `/start app`) открывает виджет-версию: одно сообщение,
внутри которого живут все экраны. Обычный `/start` всегда открывает
классический интерфейс с inline-кнопками.

- вкладки «🔥 Старты», «⭐ Избранное», «🎯 Интересы», «⚙️ Ещё»;
- список по 6 стартов на страницу; город показывается без области,
  чтобы не обрезать его посреди слова;
- первая загрузка кеширует 60 событий в сессии, поэтому следующие страницы
  листаются без запроса к backend;
- карточка старта с открытием сайта и шарингом;
- фильтры по видам спорта и регионам: до 20 регионов, по 8 на странице;
  выбор чипов происходит локально в виджете и применяется одной кнопкой;
- в карточке старта «Сайт старта» — обычная кликабельная ссылка, а не кнопка;
- уведомления с переключателями;
- ссылка-приглашение и сайт в «Ещё».

Навигация не отправляет новые сообщения: бот меняет `chat_data` виджета
через `editMessageWidgetData`, а виджет перерисовывается. Запросы кнопок
приходят как `widget_query`, ответы — `answerWidgetQuery`.

Текстовый поиск остаётся командой `/find <запрос>`: в HTML-виджете нет
поля ввода. Внутри виджета есть популярные запросы и фильтры по видам
спорта и регионам. Онбординг новых пользователей и обычный `/start`
работают в классическом интерфейсе; виджет открывается только явно через
`/app` или кнопку «Виджет-версия». Старый интерфейс с inline-кнопками
сохранён как основной и как fallback для deep links и уже отправленных
сообщений.

Открыть сразу виджет-версию можно ссылкой:

```text
https://t.me/<bot_username>?start=app
```

### Два режима в одном боте

Режим хранится у пользователя в `users.ui_mode`:

- `classic` — старый интерфейс с inline-кнопками (по умолчанию в проде);
- `widget` — новый интерфейс; включается через `/app` или кнопку «Виджет-версия».

Переключение:

- `/app` — открыть виджет-версию и переключиться на неё;
- `/classic` — вернуть классический интерфейс и открыть старое меню;
- в классическом меню «⚙️ Ещё» есть кнопка «🧪 Виджет-версия»;
- в виджете в «⚙️ Ещё» есть подсказка про `/classic`.

`/start` открывает тот режим, который выбран у пользователя. Deep links
`ev_`/`fav_` по-прежнему ведут в старую карточку, `wapp_` — в виджет.
Разные боты для этого не нужны.

## Docker

Бот входит в общий `docker-compose.yml` и `docker-compose.prod.yml`.

В production:

```bash
cp .env.prod.example .env.prod
# заполните DOMAIN, BOT_TOKEN, ADMIN_TELEGRAM_IDS
docker compose --env-file .env.prod -f docker-compose.prod.yml up --build -d
```

Nginx проксирует `/go/` в контейнер бота, поэтому трекинг работает на том же
домене: `https://sporly.ru/go/<partner_id>?uid=<chat_id>`.

## Данные

- SQLite: `app/data/sporly.db` (WAL).
- Старые JSON-файлы `subscriptions.json` и `favorite_events.json`
  импортируются один раз при первом запуске.
- Партнёрская статистика хранится в той же БД.
- Кэш событий для кнопок «избранное» — таблица `event_refs`, чистится раз в
  90 дней.
