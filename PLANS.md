# Sporly plans

## Ближайшее

- [ ] Per-source health: количество событий, время сбора, последний успешный запуск, baseline.
- [ ] Аудит полноты источников: пагинация, API, `Upcoming`/`Past`, пустые источники.
- [ ] Ручной refresh-эндпоинт, защищённый `ADMIN_TOKEN`.
- [ ] Тесты парсеров на сохранённых HTML/JSON-фикстурах.

## Надёжность обновления

- [ ] Перейти на event-level upsert вместо замены набора событий.
- [ ] Хранить `first_seen_at`, `last_seen_at`, `miss_count`, `status` (`active` / `missing` / `archived`).
- [ ] Не удалять событие после одного пропуска: помечать `missing` после N подряд неудачных refresh.
- [ ] Сохранять snapshot по каждому источнику отдельно и писать кэш атомарно.
- [ ] Хранить сырые ответы источников для replay и отладки парсеров.
- [ ] Определить retention-политику для прошедших событий.

## Алерты (отложено)

- [ ] Telegram-алерт, если источник отдал 0 событий или упал более чем на 50% два запуска подряд.
- [ ] Алерт, если кэш не обновлялся дольше двух интервалов планировщика.
- [ ] Алерт при исключении в фоновом refresh.

## Покрытие источников

- [ ] Проверить, что `Get.run` отдаёт полный фид, а не тестовую выборку.
- [ ] Добавить `RaceTime` `type=Past`, если нужен архив.
- [ ] Проверить `La Strada` и `ARF`: сейчас у них нет актуальных событий.
- [ ] Добавить fallback-сбор из VK/Telegram для источников без публичного календаря.
